# sch-pdf-compare

Compare two revisions of an electronics schematic PDF and show what changed.
The job it exists for: 21- to 85-sheet A4 sets where a changed resistor value is
a handful of pixels and nobody finds it by eye.

## Shape

A Rust core does all the thinking; `shell/` is a Qt 6 Widgets frontend that
draws what the core hands it. They meet at one flat C ABI, generated by cbindgen
into `crates/sc-ffi/include/schcompare.h` and committed.

| Crate | What it is |
| --- | --- |
| `sc-diff` | The comparison kernel: ink, tolerance, compositing, clustering. No PDF, no threads, no toolkit. |
| `sc-render` | MuPDF: open, page geometry, render a rect to pixels. Owns the CAD-enhance device. |
| `sc-match` | Pairing the two documents' sheets. |
| `sc-session` | The model: a document pair and everything asked about it. |
| `sc-ffi` | The C ABI, and the only crate the shell links. |

## Ground rules

1. **Nothing Qt-shaped crosses the ABI.** No widgets, no window handles, no
   fonts, no glyphs. If the shell needs to know something, the core answers it
   in plain data.
2. **Every fallible ABI call returns a status**: 0 success, negative failure,
   `SC_PENDING` for "not yet". `sc_last_error()` gives the sentence for a
   person.
3. **Everything the ABI hands back is borrowed**, and every function documents
   until when. Keep the `_free` count near zero.
4. **Nothing spawns a thread the frontend does not know about.** The background
   sweep is the exception and is exposed honestly: a wakeup handle to watch and
   a status to poll. No callbacks fired from a worker thread.
5. **No idle timer in the event loop.** Qt watches the core's wakeup handle with
   `QSocketNotifier` / `QWinEventNotifier` and pumps only when it fires.
6. **Customer material never enters the repository.** `samples/` is gitignored
   and stays that way — but the rule is wider than that directory, and it has
   already been broken once: a *rendered crop* of a customer schematic was
   committed to `docs/` as a README illustration and had to be taken out again.
   A picture of a drawing is the drawing. No screenshots, no crops, no test
   fixtures derived from a real set. `git ls-files | grep -iE '\.png$|\.pdf$'`
   should stay empty of anything that came from `samples/`.
7. Comments explain *why*, including the alternative that was tried and failed.
   `docs/design.md` holds the decisions, `docs/history.md` the log.

## Building

```sh
cmake -S shell -B shell/build -G Ninja
cmake --build shell/build
./shell/build/sch-pdf-compare
```

CMake drives cargo, so that is the whole build. Cargo's target directory lives
inside the CMake build tree on purpose — a shared one hands a library linked
against one toolchain's glibc to a binary built with another.

Rust alone, when working on a core crate:

```sh
cd crates && cargo test
```

### Windows

The core cross-builds and is verified under Wine by one script:

```sh
./packaging/windows/build-core.sh          # or `release`
```

MuPDF builds for the MinGW target with no special handling — this was the open
question when the project started and the answer is that it just works, in about
half a minute. `crates/.cargo/config.toml` holds the two settings it needs.

The Qt shell is **not** cross-built here: Ubuntu has no MinGW build of Qt 6. That
needs a distribution which does — Fedora's `mingw64-qt6-qtbase`, which is what
the sibling Sterna project uses — or a Qt built by hand.

## Testing

```sh
ctest --test-dir shell/build --output-on-failure   # ABI harness, Qt tests
cd crates && cargo test                            # the core
```

Every test is a plain executable, not a framework. The ones that draw also take
`--write <dir>` and dump what they drew as a PNG.

The ABI harness `crates/sc-ffi/tests/abi.c` is compiled **as C and again as C++**
with `-Wall -Wextra -Werror -pedantic`; a Rust test proves nothing about the
seam. The C++ half goes through `abi_cxx.cpp`, which `#include`s the C file —
`set_source_files_properties(... TARGET_DIRECTORY ...)` applies to the whole
directory scope and quietly relabelled both halves as C++.

There is no display in the dev container. To see the application:

```sh
xvfb-run -a --server-args="-screen 0 1400x1000x24" ./shell/build/sch-pdf-compare
# and from inside the same X server: import -window root shot.png
```
